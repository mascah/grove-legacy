### Retired workspaces (one rule, at mutation boundaries)

A branch is **retired** when it contains a retained submitted tip S
(`refs/grove/submitted/S` an ancestor of its tip, `git for-each-ref
--merged`), S is not in the target (a squash, not an ordinary merge), and
the target's first-parent history holds the squash commit whose
`Grove-Submitted` trailer names S. `standing.Retired` answers it and names
that delivery commit. Only `run` (launch) and `integrate` (delivery) ask,
so no read gains a history walk. A submission retained whose target
advance never happened (moved target, crash) is not retired, so an
interrupted delivery still retries and its branch still resumes.

- `integrate` refuses a retired branch before anything is written, naming
  the delivery commit and the fresh route; `accepted` skips retired
  branches when choosing the branch to deliver, so a kept branch never
  competes with the fresh one. A rerun whose branch reads done still goes
  to cleanup only, as today. `TestIntegrateDeliversReopenedWorkAgain`
  becomes the refusal; the "merge the target and hand off again" advice in
  the carried-work refusals becomes "start fresh from the target".
- `run` refuses a retired branch named with `--branch`. With the default
  name, a retired `worktree-IDS` is skipped for `worktree-IDS-2`, `-3`, …,
  the first that is absent or not retired, so a reopened item's fresh
  workspace never collides with a kept one. The kept one stays readable to
  `versions`, `workspace` and the board.

### Fresh base and bounded proposal admission

A new workspace starts from the configured target's tip, not the launching
checkout's HEAD; without `target:` it keeps HEAD, as today. A reused or
existing branch is resumed as it is (pre-delivery fixes, interruption):
existing assignments are not reinterpreted.

When HEAD is not the target tip, the selected records are taken from
HEAD's committed copies (the launching checkout, as today):

- Each selected record the target lacks is **admitted**, with, transitively,
  every record its relationships (`depends_on`, `members`, `blocks`,
  `relates_to`, `work`) name that the target lacks, which validation
  requires, and each plan or question whose `work` or `blocks` names a
  selected member and that the target lacks. Only records: no code,
  configuration, harness file, body-linked document or unrelated record;
  `context` names a body link the workspace lacks as missing.
- A selected record the target holds with different bytes is a changed
  input: the launch is refused, naming both revisions, to deliver or
  reconcile it first. An admitted path the target holds is never
  overwritten.
- Preview lists each admitted path with its revision and the source
  commit; the digest covers them. Start copies those exact blobs into the
  new worktree, loads the project there (any diagnostic refuses, removing
  the worktree and branch it just made) and commits them as
  `chore: admit IDS from BRANCH` with the paths and `Grove-Admitted-From:
  COMMIT`. The launch records `source` and `admitted`. The commit is part
  of the candidate branch and is delivered with it.

### Cleanup on by default, keep by choice

- `integrate` cleans up after a proved delivery unless kept: `--keep`, or
  the newest attempt on that branch launched with `run --keep` (recorded
  as `keep` in attempt.json). `--cleanup` stays accepted as the default
  spelled out. The sweep's delegated integration therefore cleans up too.
- Cleanup keeps, with the reason, what it does today (changed tip, dirty,
  untracked or ignored files, cwd) and also: a running or orphaned attempt
  whose worktree it is (live ownership), and a registered path that no
  longer holds that branch's checkout (a replaced path). A kept workspace
  is a reported fact, not a failure: delivery and Done stand and the exit
  is 0; a later `integrate ID` retries cleanup only.
- The board's `i` asks keep-or-clean with clean the default.

## As built

Review changed two things this plan chose. Retirement is asked by every
verb that would act on a branch, not only `run` and `integrate`: `approve`,
`feedback` and so `resolve` refuse there too, and `integrate` refuses work in
review as well as accepted. [commands.md](../docs/commands.md#retired-branches)
owns that list. `--cleanup` is not merely the default spelled out: it
overrides a `run --keep`.
